# Twinflare (Tangible Rocket Game) browser game

Keyboard game and browser-side Arduino integration for `Rocket-Game-Construction-Workflow.md`. Vanilla HTML, CSS and JavaScript with Canvas 2D. No framework and no build step. The only binary asset is `assets/menu-wallpaper.png` (title art generated by the team); every in-game shape is drawn in code and every sound is synthesised with Web Audio.

## Screens

- **Menu**: full-screen 16:9 frame over the title art, letterboxed on other aspect ratios. Mission select (Practice, Solo, Co-op, Controls, Options) sits in the calm zone below the title. A systems panel connects/disconnects the Arduino, calibrates one or two rockets and switches between Arduino and keyboard input. Arrow keys or W/S move through the list, Enter launches, F toggles fullscreen.
- **Options**: target score, course seed, sound and menu music. The theme starts on the first click or key press (browser autoplay rules), fades out when a round starts and returns on the menu. Saved in `localStorage` under `twinflare.options`. An empty seed means a new random course every round.
- **Game**: a 16:9 playfield (1600x900 world units) fills the screen and is letterboxed on other ratios. Asteroids, gates, station blocks and strafing enemy drones form the course; drones fire aimed plasma that can be dodged or intercepted. Player 1 and Player 2 instrument panels remain in the top corners. In solo modes the right panel shows mission details instead.
- **Pause** and **Debrief** dialogs use the same HUD styling.

Fonts load from Google Fonts (Chakra Petch, Rajdhani) and fall back to Bahnschrift / Segoe UI offline.

## Run

ES modules and (later) Web Serial both need `http://localhost`, not `file://`.

```bash
cd rocket-game
python -m http.server 8000
```

On macOS use `python3 -m http.server 8000`. Open <http://localhost:8000> in desktop Chrome or Edge (Safari and Firefox have no Web Serial).

## Test

```bash
cd rocket-game
node --test tests/*.test.js
```

The simulation has no DOM dependency, so the tests run under Node with a scripted input source.

## Controls

| Player | Steer | Fire |
|---|---|---|
| P1 | A / D | Space |
| P2 | ← / → | Enter |

`P` or `Esc` pauses. `F` toggles fullscreen. Holding a steer key ramps the bank angle to 20°; steering uses the same dead zone (2.5°) and gain (full speed at 20°) that the tilt sensor will use.

## Modes

- **Practice**: no timer or hull loss, with asteroids and non-firing enemy drones for aiming practice.
- **Solo Mission**: 90 s, full field width, 3 hearts, reach the target score.
- **Co-op Mission**: both rockets share the same field, shared 90 s timer and combined score, target score configurable. An eliminated player watches while the partner continues. Both eliminated ends the round; success needs at least one survivor and the target reached.

## Health

Health is tracked in half hearts (6 halves = 3 hearts).

| Event | Cost |
|---|---|
| Rock, block or gate bar | 1 heart, destroys the hazard, 1 s invulnerability |
| Enemy drone or red plasma | 1 heart; drones award 20 points when destroyed |
| Rocket-to-rocket crash (co-op) | ½ heart to each rocket, rockets pushed apart, 0.75 s crash cooldown per rocket |

The Markdown design and workflow now reflect the implemented 16:9 shared arena and rocket-to-rocket crashes. The older DOCX exports still require regeneration before they should be used as wiring or gameplay references.

## Layout

```
js/core        constants, seeded RNG, fixed-step loop (60 Hz, stall guard)
js/input       InputSource, KeyboardInput, strict R1 parser and Web Serial input/calibration
js/sim         Game (authoritative state, timer, score), Player, Spawner, drones and entities
js/render      Renderer: vector rockets, enemies, plasma, parallax field and effects
js/ui          Hud: DOM instrument panels and top bar, updated per frame
js/audio       Sfx: Web Audio effects. Music: synthesised menu theme (16 s loop in D minor)
js/feedback    FeedbackSink and H/B/X/M hardware-feedback commands over the same serial port
tests          node --test simulation tests
```

## Rules implemented

- Input is sampled once per fixed 60 Hz step. Physics never advances per input event or per serial packet.
- A trigger release is required before Start and Resume. Unhealthy input clears steering and disarms fire.
- Held fire spawns at most one projectile every 250 ms. One projectile destroys one target and scores once.
- Enemy drones strafe, aim at the nearest living player and fire bounded plasma bolts; player shots can intercept them.
- Overlapping a hazard for many frames costs one heart, destroys that hazard and grants 1 s invulnerability.
- Two living rockets overlapping are separated and each charged half a heart, at most once per crash cooldown.
- Course density scales with field width: about one hazard slot per 400 px, and gates have one 200 px opening per 800 px so a wide field never becomes a single wall.
- Pause (user, hidden tab, or a frame gap over 250 ms) freezes the timer, entities and firing.
- The course is generated from a seed shown on the results screen so trials can be matched.

## Arduino input contract

For literal component-by-component construction instructions, use [Twinflare Physical Assembly Tutorial](../Twinflare-Physical-Assembly-Tutorial.md).

Serve the game on localhost and use desktop Chrome or Edge. Close Arduino Serial Monitor before choosing **Connect Arduino**, because only one program can normally own the port.

The Uno must send one newline-terminated combined record at approximately 50 Hz and 115200 baud:

```text
R1,1234,24680,-750,0,1,430,1,1
```

Fields are: protocol version, unsigned sequence, Uno uptime in milliseconds, P1 roll in hundredths of a degree, P1 fire, P1 health, P2 roll, P2 fire and P2 health. Fire is 0/1. Health is 0 starting, 1 valid or 2 fault. P1 uses sensor address 0x68 and P2 uses 0x69.

Connection workflow:

1. Upload `twinflare_firmware` from [rocket-firmware](../rocket-firmware/README.md) and close Serial Monitor.
2. Open the game from `http://localhost:8000` in Chrome or Edge.
3. Choose **Connect Arduino** and select the Uno/clone port.
4. Wait until the Systems panel reports healthy data.
5. Hold the required rocket or rockets level and still, release both fire buttons, then choose **Calibrate**.
6. When the panel reports Ready, launch Solo or Co-op. The game automatically uses Arduino input after connection; **Use Keyboard** remains available from the menu.

The parser rejects malformed, overlong, duplicate and out-of-order records. Missing healthy data for more than 250 ms clears input and pauses the game. A board reset invalidates calibration. Reconnect and calibration controls appear inside the pause dialog, and Resume stays disabled until every required controller is ready.

The browser can also send bounded feedback commands over the same port: `H,1`, `H,2`, `B,1`, `B,2`, `X`, `M,1` and `M,0`, each newline terminated. Firmware support for those commands can be added when the LED/buzzer circuit is tested; lack of output-command handling does not block controller input.

## Debug hook

`window.rocketDebug.step(n)` advances the current game by `n` fixed steps and redraws. `window.rocketDebug.game` exposes the live `Game` instance. `window.rocketDebug.noStall = true` disables the stall pause while stepping manually. Used for manual testing only.
